# application

![Version: 1.0.0](https://img.shields.io/badge/Version-1.0.0-informational?style=flat-square) ![Type: application](https://img.shields.io/badge/Type-application-informational?style=flat-square)

Generic Helm chart for Deployment, StatefulSet, DaemonSet, Job and CronJob

The chart can also create the resources a workload needs: Services, Gateway API routes and ListenerSets, ServiceAccounts with Roles and RoleBindings, ConfigMaps, Secrets, ExternalSecrets, PersistentVolumeClaims, NetworkPolicies, Cilium network policies, ServiceMonitors and PodMonitors.

## Requirements

Kubernetes: `>=1.30.0-0`

## Installing the Chart

### Helm repository

```bash
# Add the repository
helm repo add fawzihmouda https://fawzihmouda.github.io/helm-charts

# Install the chart
helm install my-app fawzihmouda/application -f values.yaml
```

## Configuration

Each release runs one workload. The top-level key names its type: `deployment`, `statefulset`, `daemonset`, `job` or `cronjob`. The only required values are that key and the image of each container.

```yaml
deployment:
  replicas: 2
  image:
    repository: ghcr.io/example/my-app
    tag: 1.0.0
  additionalContainers:
    shipper:
      image:
        repository: fluent/fluent-bit
        tag: "3.2"
service:
  ports:
    http:
      port: 80
```

- The main container's fields, such as `image`, `env`, `probes` and `resources`, sit directly under the type key. The main container takes the release name.
- `additionalContainers` and `initContainers` hold the other containers, keyed by name. `dependsOn` and `persistence.<name>.advancedMounts` refer to the main container as `main`.
- Options for the workload type sit under the same key, such as `schedule` for a CronJob or `volumeClaimTemplates` for a StatefulSet.
- `service` configures the one Service, which targets the workload.
- `rawResources` deploys any resource the chart doesn't create, such as an Ingress.

Read through the [values.yaml](https://github.com/fawzihmouda/helm-charts/blob/main/values.yaml) file. Its comments describe every value. The [CI values](https://github.com/fawzihmouda/helm-charts/tree/main/ci) contain working setups that may prove useful as well.

The chart sets no pod or container security context by default. Set `defaultPodOptions.securityContext` for every pod, and `securityContext` on each container.

## Contributing

Install the tools pinned in `.mise.toml`, then the Git hooks:

```bash
mise install
pre-commit install
```

The hooks lint the chart on each commit and run the unit tests on each push. Pull requests also install the chart on k3s for each supported Kubernetes version.
